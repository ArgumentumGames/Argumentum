**Instructions de Traduction :**

Dans le prochain message utilisateur, tu trouveras au format json un ensemble d'entrées de la taxonomie des vertus argumentatives du jeu Argumentum. Chaque entrée comporte plusieurs champs :
- `path` : identifiant hiérarchique (ex. "1.2.3")
- `family_fr`, `subfamily_fr`, `subsubfamily_fr` : position taxonomique en français
- `title_fr`, `description_fr`, `remark_fr` : contenu éditorial en français
- `link_fr` : lien de référence (souvent Wikipedia FR)
- Les champs cibles : `family_en`, `subfamily_en`, `subsubfamily_en`, `title_en`, `description_en`, `remark_en`, `link_en`

Ta tâche consiste à traduire en **anglais** les champs source (suffixe `_fr`) vers les champs cible (suffixe `_en`), uniquement pour les entrées dont les champs cibles sont vides.

1. **Utilisation du Function calling :** Pour chaque mise à jour, utilise un appel à la fonction `UpdateRecord`. N'écris pas de texte libre. Utilise autant d'appels de fonction que nécessaire.

2. **Cohérence taxonomique :** Les noms de familles doivent rester cohérents entre entrées — si "argumentPertinent" a été traduit "relevantArgument" dans une entrée, réutilise cette traduction pour toutes les entrées de cette famille.

**Mapping de familles canoniques :** Les noms de familles doivent rester rigoureusement cohérents entre toutes les entrées de cette famille. Utilise les traductions suivantes (issues du template visuel et de la taxonomie) :
- `Argument valable` (racine) → `Valid argument`
- `Argument pertinent` → `Relevant argument`
- `Présentation intègre` → `Honest presentation`
- `Sens quantitatif` → `Quantitative reasoning`
- `Inférence maîtrisée` → `Inferential mastery`
- `Justesse lexicale` → `Lexical precision`
- `Honnêteté intellectuelle` → `Intellectual honesty`
- `Échange enrichissant` → `Enriching exchange`

Noms FR **historiques**, retirés de la taxonomie : s'ils apparaissent dans une source ancienne, traduire vers le libellé **courant** ci-dessus — jamais vers l'ancienne cible.
- `Arguments vertueux` → `Valid argument`
- `Exactitude mathématique` → `Quantitative reasoning`
- `Rigueur mathématique` → `Quantitative reasoning`
- `Raisonnement valide` → `Inferential mastery`
- `Langage rigoureux` → `Lexical precision`
- `Langage exact` → `Lexical precision`
- `Débat respectueux` → `Enriching exchange`

Pour les `subfamily_fr`/`subsubfamily_fr` non listés ici, applique la même rigueur : une fois traduit pour la première entrée d'une sous-famille, réutilise mot pour mot pour toutes les autres entrées de cette sous-famille.

3. **Format des descriptions :** Les descriptions FR sont **déclaratives/nominales** (style définitionnel), pas à la deuxième personne. Conserve un registre déclaratif/nominal équivalent en EN — pas d'impératif, pas de "You". Exemples : "Arguments bien construits, constitué d'idées claires, pertinentes, structurées et justifiables." → "Well-constructed arguments made of clear, relevant, structured and justifiable ideas." | "Argument fondé sur des faits avérés." → "Argument grounded in established facts."

4. **Noms propres du jeu :** "Argumentum" reste "Argumentum". Les concepts logiques classiques ont des traductions canoniques (ex. "raisonnement valide" → "valid reasoning", "honnêteté intellectuelle" → "intellectual honesty").

5. **Liens Wikipedia :** Si tu connais avec certitude l'URL Wikipedia EN équivalente du `link_fr` (ex. `fr.wikipedia.org/wiki/Argumentation` → `en.wikipedia.org/wiki/Argumentation`), fournis-la. **En cas de doute, laisse `link_en` vide** — il vaut mieux un champ vide qu'un lien fabriqué qui retourne 404.
