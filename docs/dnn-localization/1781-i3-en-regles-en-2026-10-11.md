## Objet

Écrire les valeurs **anglaises** des 5 fiches Game Rule de la préprod (École 11378,
Bingo 11380, Beau-parleur 11387, Moulin 11388, Parlote 11389), source = **cartes**
(décision owner Q-10-09-1 **(b)**), coordonnée `EntityId + StaticName + DimensionID=7`

prouvé vivant** (expérience ci-dessous), mais **verrouillé en aval par DNN** :

## Ce qui est écrit (préprod, additif, réversible)

**27 valeurs** — générées de `Cards/Rules/Argumentum Rules - Cards.csv`, colonne
`Text_en` (parallèle intégral mesuré : chaque section FR a sa contrepartie EN) :

| Attribut | Source CSV (EN) | Contenu |
|---|---|---|
| Title | titre de la section `##` de couverture | texte brut — « The school of liars », « Argumentative mixology bingo », « The Last Smooth Talker », « The Smooth-Talk Mill », « The Coinched Chat » |

| Installation | « Setup » | md→html |
| Variants | « Variants[:] » (École + Moulin uniquement) | `<ul>` depuis les items `* ` |
| Content | toutes les autres sections dans l'ordre (7/3/5/5/6 selon la fiche) | `<h2>/<h3>` + md→html |

Structure identique au R-site FR ([`1502-r-site-ecriture-2026-10-09.md`](1502-r-site-ecriture-2026-10-09.md))
: mêmes fonctions md2html/nkey (copie verbatim de `rsite-gen.py`), même découpage
par sections de cartes. **Aucun squelette stocké n'existe en EN** (0 valeur
dimensionnée avant ce geste) : le Content EN est construit intégralement du corpus,
contrairement au FR qui préservait le HTML stocké comme autorité structurelle.

Mécanique d'écriture (writer transactionnel, scratchpad `i2/en-writer.ps1`, jamais
commis — mot de passe inline) : pour chaque couple — garde (0 lien dim-7 vivant +
exactement 1 valeur préexistante), `INSERT TsDynDataValue (EntityId, AttributeId,
Value)` → `SCOPE_IDENTITY()` → `INSERT TsDynDataValueDimension (ValueId, 7, ReadOnly=0)`.
Vérification post-commit octet à octet : **27/27, 0 écart**. Convention mesurée sur
les rangées zone 2 existantes (une rangée de valeur **par langue**, lien ReadOnly=0).

Divergence documentée : le FR Variants École garde 2 items owner byte-identiques
(edits web FR sans contrepartie corpus) ; l'EN n'avait rien de stocké, donc ses items
viennent tous du corpus. Cosmétique constatée, non corrigée (corps gelé) : les titres
EN mélangent Title Case (« The Last Smooth Talker ») et phrase case
(« The school of liars ») — décision (b) : le corpus fait foi.

**Inverse** : `en-inserted-ids.json` (scratchpad `i2/`) porte les 27 ValueId —
`DELETE FROM TsDynDataValueDimension WHERE ValueId IN (…)` puis `DELETE FROM
TsDynDataValue WHERE ValueId IN (…)` + recycle.

## L'expérience qui prouve le mécanisme (et localise le verrou)

Après l'écriture + recycle, la fiche `?language=en-US` servait **encore le français**
(page re-rendue — ViewState neuf —, `<html lang="en-US">`, UI DNN en anglais).
Diagnostic par marqueurs temporaires sur l'attribut Summary de l'École :

1. **Marqueur dimension 6 (fr-FR)** inséré → visible sur la fiche FR **et** sur la
   fiche EN (`/language/en-US/…`).
2. **Marqueur dimension 7 (en-US)** inséré à son tour → **jamais servi**, ni FR ni EN.

Lecture : la résolution de langue du moteur est **vivante** (une valeur dimensionnée
battant la valeur sans dimension le prouve), et pour une requête en-US la chaîne de
priorités résout `fr-fr` **avant** le repli sans dimension — la culture vue par 2sxc
est fr-fr même sur une URL `/language/en-US/`. Les deux marqueurs ont été supprimés
(valeurs + liens, transaction, recycle) ; la page FR est revenue à l'état antérieur
(contrôle servi). État final mesuré : **dim 7 : 27 valeurs, rien d'autre** sur les
5 entités.

## §5. Correction (12/10) : le débloqueur réel est l'alias culturel `/en`

Chaîne mesurée dans l'ordre — chaque maillon vérifié avant le suivant :

1. **CL activé (11/10 14:17Z, GO ai-01)** : bascule du réglage seul
   (`ContentLocalizationEnabled=True` + recycle), instantané Tabs identique,
   non-régression FR 7/7. **Insuffisant seul** : la fiche `/language/en-US/…` reste
   100 % FR — l'URL bascule la locale du **thread** (`GetPageLocale` → `SetThreadCultures`),
   jamais `PortalSettings.CultureCode`, posé à la **construction** du portail et piloté
   par la culture d'**onglet** (modèle « onglet par langue », refusé par l'architecture).
   2sxc v21 lit `CmsContext.Culture.CurrentCode` = `fr-fr` sur les deux URLs, DLL
   `ToSic.Sxc.Dnn.Core` → `PortalSettings.get_CultureCode`, zéro `CurrentUICulture`.
2. **Arbitrage ai-01 (11/10 22:54Z)** : ordre ① mécanisme natif DNN (alias `/en`
   rattaché `en-US`, SUPPOSÉ, à sonder) ② sinon pont de thème (~3 lignes
   `theme-body.ascx` alignant `CultureCode` sur le thread). **Le pont n'a jamais été
   nécessaire.**
3. **Essai ① gagnant (12/10 ~02:30Z)**, vérifié dans la source AVANT le geste :

   HTTPAlias='dnn.argumentum.myia.io/en', CultureCode='en-US', IsPrimary=0)` (id 2010)

4. **CANONICALURL sondé avant** : mode « canonical » de DNN 10 n'émet pas de 301 —
   au plus un `<link rel="canonical">` (aucun observé sous `/en`) ; la préprod sert
