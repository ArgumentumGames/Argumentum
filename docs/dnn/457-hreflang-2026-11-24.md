no setting touched, no database read. Every figure below names the command that reproduces it; where a claim
is an inference rather than a measurement, the section says so.

Bytes are `curl --compressed -s … | wc -c` — the decoded body as delivered, terminator included.

```bash
curl --compressed -s -m 150 https://www.argumentum.games/en/ | grep -o 'hreflang=' | wc -l    # 0
curl --compressed -s -m 150 https://www.argumentum.games/en/ | grep -o 'rel="canonical"' | wc -l  # 1
```

The canonical mirrors the **request path verbatim**, including its casing and its optional trailing slash:

| Request | Canonical emitted |
| --- | --- |
| `https://www.argumentum.games/en/` | `https://www.argumentum.games/en/` |
| `https://www.argumentum.games/en` | `https://www.argumentum.games/en` |
| `https://www.argumentum.games/EN/` | `https://www.argumentum.games/EN/` |

That verbatim shape is what the skin emits on a **non-bare** view (see §3, the `bareView` branch): on a bare
tab view it replaces the request-path canonical with the composed culture URL, which is lower-cased by the
alias row and carries the composed path. Two independent probes (`/en` and `/EN/`) therefore say the
production pages are **not** taking the bare-view branch — the head code runs, and stops before the
alternates.

`hreflang` was already 0 on these pages before the cutover of 2026-11-24 (measured the same week by the
P23-32 external check and the P23-34 index), and server-side language negotiation still serves all eight
cultures (`lang="fr-FR"` … `lang="zh-CN"` on the eight pages). **This is not a regression of the cutover.**

## 3. The code: one emitter, six gates

`DNNPlatform/Portals/_default/Skins/2shineBS5/controls/theme-body.ascx:246` calls `EmitLanguageAlternates()`
(defined at `:284`). Its gates, in the order the code takes them:

1. at least **2 enabled locales** for the portal (`LocaleController.GetLocales`);
2. a `Head` control found (`Page.FindControl("Head") as HtmlHead`);
3. the portal's **default language** has a **culture-coded alias row** (`PortalAlias.CultureCode`) — otherwise
   the request-path canonical is emitted and the method returns;
4. `Globals.NavigateURL(tabId, …, defaultLanguage, …)` returns a non-empty path — the neutral tab path;
5. per culture, a **culture-coded alias row** exists, otherwise that culture is skipped (and `emitted` stays
   put);
6. alternates are appended only on a **bare tab view** and only when `emitted >= 2`; `x-default` only when the
   default culture's URL is known.

The alias rows are read deliberately instead of composing `/<culture>/` by hand — the comment at `:277-283`
records why: `NavigateURL(…culture…)` returns **neutral** URLs when portal content localization is disabled
(#1991), which would collapse the eight alternates onto one URL, while the alias rows serve the eight cultures
in both states of that flag.

**There is no other emitter.** In the tracked DNN export, `hreflang` appears only inside vendor JavaScript
(admin bundles, Monaco, the 2sxc editors):

```bash
git grep -ril "hreflang" -- DNNPlatform | grep -v "Skins/2shineBS5"   # 25 files, vendor JS only — no ASP.NET
git grep -c "hreflang" -- DNNPlatform/Portals/_default/Skins/2shineBS5  # theme-body.ascx:4
```

The platform DLLs are not tracked, so this statement is scoped to the export: it says no **declared** emitter
exists in the tree, not that no assembly could carry one.

## 4. What the measurement separates — and what it does not

`rel="canonical"` is on every production page ⇒ gates 1 and 2 pass. The alternates are absent ⇒ gate **3**,
**4** or **6** is closed. Gate 6 depends on 3 and 4: a bare view needs `currentUrl`, i.e. the current
culture's alias row. So production stops on a **portal-alias fact**, a **`NavigateURL` fact**, or both.

Those two are not separable over HTTP: they differ only by a read of the portal's alias rows, which this grain
did not make (no database read from this lane).

**Hypothesis, not a measurement**: production serves `/en/`, `/ar/`… with 200, and DNN resolves a culture
prefix from a portal alias row — so the rows very likely exist, but their `CultureCode` may be written in a
short form (`en`, `fr`) while the locale keys are full codes (`en-US`, `fr-FR`). The lookups are
`OrdinalIgnoreCase` on the **full** code, so `en` would never match `en-US`; gate 3 would close, the method
would return, and every observation of §1 would follow. The preprod, which emits, is the configuration that
works: its alias rows are culture-coded (`dnn.argumentum.myia.io/en` …), as the nine hrefs show.

## 5. The proposal

**Step 0 — read, do not fix by trying.** One read-only query on the server that holds the database
(ai-01 or web2), ~1 min:

```sql
SELECT PortalID, HTTPAlias, CultureCode, IsPrimary
FROM   PortalAlias
WHERE  PortalID = 1
ORDER  BY HTTPAlias;
```

It decides between two shapes of the same gesture — aligning the portal's alias rows with the locale codes of
the eight enabled languages:

| What the SELECT shows | The gesture |
| --- | --- |
| no culture-coded rows | insert the eight culture-coded rows (Site Settings → Portal Aliases; HTTP Alias = served host + `/<code>`, Culture = the language). The URLs these rows compose already answer 200 (8/8, §1) |
| rows coded `xx` while the locale is `xx-YY` | update `CultureCode` on those eight rows only; no alias host changes |

**Rollback, per shape.** *Rows inserted*: delete exactly those eight rows — their `HTTPAlias` values are
written down **before** the gesture (that list is the rollback). *Rows updated*: restore the eight previous
`CultureCode` values from a backup taken in the same session
(`SELECT * INTO PortalAlias_20261124_bak FROM PortalAlias WHERE PortalID = 1`), drop the backup only after the
control, never before.

**Control after the gesture** (read-only, from any seat):

```bash
for p in "" en/ ru/ pt/ es/ ar/ fa/ zh/; do
  curl --compressed -s -m 150 "https://www.argumentum.games/$p" | grep -o 'hreflang=' | wc -l   # 9 on each
done
# and each href answers 200, unchanged:
curl --compressed -s -m 150 -o /dev/null -w '%{http_code}\n' https://www.argumentum.games/zh/
```

Expect **9** `hreflang` and **exactly 1** canonical per bare home page, and **0** `hreflang` on a detail page
(the preprod's control of §2). No pool recycle: the head is built per request; if the alias table turns out to
be cached, touch `web.config` on the site (the documented way — never `iisreset`), and removing the touch is
the reverse.

**Alternative, only if the SELECT shows the rows already correct.** The stop would then be gate 4
(`NavigateURL` returning empty), and the fix belongs to the **theme**: when `NavigateURL` yields nothing,
compose each culture's URL from the current host and the tab path. Rollback: revert the `.ascx`, recycle the
pool. It is not the first proposal: it moves URL composition into the theme, where the comment at `:277-283`
deliberately anchored it on the alias rows.

⛔ Nothing was executed here. The production write and its rollback are web2's, under ai-01's go.

## 6. What is not measured here

- **The production portal's alias rows** — no database read from this lane; §4 names the query that closes it.
- **The version of the skin file served by production** — its presence is *inferred* from the canonical it
  emitted, not read: the production tree is not on this seat.
- **The effect on crawlers** (Search Console, re-indexation) — outside this grain, and not observable from
  here.
- **`/en` and `/EN/` were probed on the home tab only**; another tab could behave differently, though the code
  path is the same.
- The eight cultures being *enabled locales* is **assumed** from the served pages and from the theme's comment;
  gate 1 itself was not read from the portal.
